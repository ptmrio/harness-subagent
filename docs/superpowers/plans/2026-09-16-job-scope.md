## Locked protocol (normative)

### After this change, how the skill works

Routing is unchanged. Utterance → user config → ask once. One job per spawn. Parent synthesizes.

| Path | When | Stages (unchanged) |
|---|---|---|
| **S Spike** | Unknown fact / feasibility. No build. | research or unstuck. Stop. |
| **B Bounded** | Change you could describe in a sentence. | implement → code-review [→ visual if UI] → parent coherence |
| **A Architectural** | New subsystem / project / shared interface. | research → spec → plan → improve → implement → code-review [→ visual] → parent coherence |

Default skips unchanged (research/spec/plan/improve/visual off unless their un-skip trigger). Improve stays report-only. Parent coherence is always `self`.

This operator’s config (not the protocol): `spec`/`plan`/`implement` = `self`; `*-ui` = Claude; `writer` = Grok; `research`/`improve`/`code-review` = Codex; `improve` and `code-review-visual` pin Astra.

### What *does* change: child scope

**One rule, all roles:**

The brief names a **job** (objective), starting paths, product locks, and hard exclusions.

- Stay inside that job. Named paths are where to start, not a cap.
- Read what a claim or gate needs. Write jobs may edit what the job requires; report extra paths edited.
- Product locks and explicit exclusions bind. Do not add features, drive-by refactors, or a second job.
- Review / research / improve / visual do not edit application files. Improve does not edit the plan; it reports KEEP / CUT / ADD / SPLIT. Extra files Improve opened go under existing COVERAGE.

Parent briefs: pre-research belongs in **What was already tried**. **Where to look** is a starting set plus bounded commands, plus locks/exclusions. Do not jail a file to one function or locator unless that *is* the product lock. Every brief pastes the shared scope section once (with the role return contract), not a second copy under every heading.

Windows Cursor parent Shell: on hosts reporting unavailable filesystem isolation, request full Shell permissions for the spawn call. A parent Shell refusal **before the script starts** is not a failed spawn launch. Two failed launches of the script → stop; answer from parent evidence and mark the harness UNVERIFIED. Do not invent a third quoting recipe.
